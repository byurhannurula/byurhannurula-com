Building a homelab has been one of the most rewarding projects I've undertaken as a developer. It's not just about having cool hardware—it's about learning, experimenting, and taking control of your digital life. In this post, I'll walk you through my entire setup, from hardware choices to the services I run.

## Why Build a Homelab?

Before diving into the technical details, let's talk about why you might want a homelab:

- **Learning**: Nothing beats hands-on experience with real infrastructure
- **Privacy**: Keep your data under your control, not in someone else's cloud
- **Cost savings**: Long-term, self-hosting can be cheaper than cloud subscriptions
- **Customization**: Build exactly what you need, how you need it
- **Fun**: Let's be honest, it's just cool to have your own datacenter

<Callout type="info" title="Starting Small">
  You don't need expensive enterprise hardware to start. An old laptop or a Raspberry Pi is enough
  to begin your homelab journey.
</Callout>

### Storage Architecture

Storage is critical in a homelab. I use a tiered approach:

```
┌─────────────────────────────────────────────────────────┐
│                    Storage Tiers                         │
├─────────────────────────────────────────────────────────┤
│  Tier 1: NVMe SSD (500GB)    → VMs, Databases           │
│  Tier 2: SAS SSD (2TB)       → Containers, Hot Data     │
│  Tier 3: HDD RAID (16TB)     → Media, Backups, Archives │
│  Tier 4: Synology NAS (40TB) → Cold Storage, Offsite    │
└─────────────────────────────────────────────────────────┘
```

## Network Setup

Proper networking is the backbone of any homelab. Here's my network topology:

### VLAN Configuration

I separate my network into multiple VLANs for security and organization:

| VLAN ID | Name       | Subnet       | Purpose                |
| ------- | ---------- | ------------ | ---------------------- |
| 1       | Management | 10.0.1.0/24  | Network devices        |
| 10      | Trusted    | 10.0.10.0/24 | Personal devices       |
| 20      | IoT        | 10.0.20.0/24 | Smart home devices     |
| 30      | Servers    | 10.0.30.0/24 | Server infrastructure  |
| 40      | DMZ        | 10.0.40.0/24 | Public-facing services |

```yaml title="network-config.yml"
networks:
  - name: "Servers"
    vlan_id: 30
    subnet: "10.0.30.0/24"
    gateway: "10.0.30.1"
    dhcp:
      enabled: true
      start: "10.0.30.100"
      stop: "10.0.30.254"
    firewall:
      - allow: internal
      - deny: iot_to_servers
```

<Callout type="warning" title="Security First">
  Always isolate IoT devices on their own VLAN. Many smart devices have poor security and can be
  entry points for attackers.
</Callout>

## Virtualization with Proxmox

I use Proxmox VE as my hypervisor. It's free, powerful, and has an excellent web interface.

### VM Templates

I maintain several VM templates for quick deployment:

```bash title="Terminal"
# Create a cloud-init enabled Ubuntu template
wget https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64.img

qm create 9000 --name "ubuntu-cloud" --memory 2048 --cores 2 --net0 virtio,bridge=vmbr0
qm importdisk 9000 jammy-server-cloudimg-amd64.img local-lvm
qm set 9000 --scsihw virtio-scsi-pci --scsi0 local-lvm:vm-9000-disk-0
qm set 9000 --boot c --bootdisk scsi0
qm set 9000 --ide2 local-lvm:cloudinit
qm set 9000 --serial0 socket --vga serial0
qm set 9000 --agent enabled=1
qm template 9000
```

## Services I Self-Host

### Infrastructure Services

These are the foundational services that everything else depends on:

```yaml title="docker-compose.yml"
version: "3.8"

services:
  traefik:
    image: traefik:v3.0
    command:
      - "--api.dashboard=true"
      - "--providers.docker=true"
      - "--entrypoints.web.address=:80"
      - "--entrypoints.websecure.address=:443"
      - "--certificatesresolvers.letsencrypt.acme.tlschallenge=true"
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./traefik:/etc/traefik

  portainer:
    image: portainer/portainer-ce:latest
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - portainer_data:/data
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.portainer.rule=Host(`portainer.home.lab`)"

  homepage:
    image: ghcr.io/gethomepage/homepage:latest
    volumes:
      - ./homepage:/app/config
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.homepage.rule=Host(`home.lab`)"
```

## Monitoring & Observability

You can't manage what you can't measure. Here's my monitoring stack:

### Prometheus + Grafana

```yaml title="docker-compose.monitoring.yml"
services:
  prometheus:
    image: prom/prometheus
    volumes:
      - ./prometheus:/etc/prometheus
      - prometheus_data:/prometheus
    command:
      - "--config.file=/etc/prometheus/prometheus.yml"
      - "--storage.tsdb.retention.time=30d"

  grafana:
    image: grafana/grafana
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=secret
    volumes:
      - grafana_data:/var/lib/grafana

  node-exporter:
    image: prom/node-exporter
    network_mode: host
    pid: host
    volumes:
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
```

### Key Metrics I Track

- **CPU/Memory/Disk**: Basic resource utilization
- **Network throughput**: Bandwidth usage per VLAN
- **Container health**: Restart counts, resource usage
- **SSL certificate expiry**: Never get caught with expired certs
- **Backup status**: Ensure backups are completing

<Callout type="success" title="Alerting is Key">

</Callout>

## Backup Strategy

The 3-2-1 rule: 3 copies, 2 different media types, 1 offsite.

```bash title="backup.sh"
#!/bin/bash

export RESTIC_REPOSITORY="sftp:backup@nas:/backups/homelab"
export RESTIC_PASSWORD_FILE="/root/.restic-password"

# Backup important directories
restic backup \
  /home \
  /etc \
  /var/lib/docker/volumes \
  --exclude="*.tmp" \
  --exclude="node_modules" \
  --exclude=".cache"

# Prune old backups
restic forget \
  --keep-daily 7 \
  --keep-weekly 4 \
  --keep-monthly 12 \
  --prune

# Verify backup integrity
restic check
```

## Lessons Learned

After years of running a homelab, here's what I've learned:

1. **Start simple**: Don't try to build everything at once
2. **Document everything**: Future you will thank present you
3. **Automate early**: Manual processes don't scale
4. **Plan for failure**: Hardware fails, have backups and redundancy
5. **Security matters**: Treat your homelab like a production environment
